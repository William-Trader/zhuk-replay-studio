# 改造路线图（工业级）

目标：成为**完整的K线模拟训练产品** —— 数据随时可用、回放可信、撮合可对账、训练有闭环、架构可维护。
每阶段都必须「可验证」：有测试或可复现的验收步骤，不允许"感觉好了"。

## P0 ✅ 工程化地基（本轮完成）
- [x] 领域层 `src/domain/dataset.ts`：数据集意图 / 游标落地 / 回放区间有效性 → 纯函数
- [x] 单测 `tests/dataset-domain.test.ts`（含 3 个历史 bug 的回归）
- [x] App 接到领域层，规则不再散落组件
- [x] 静态质量门 `scripts/check.mjs`（文件体量/any/console/架构边界/TODO）
- [x] 校验流水线 `scripts/ci.sh` + `npm run typecheck|lint|ci`
- [x] `docs/ARCHITECTURE.md`（分层、数据流、8 条不变量、可观测性）
- **验收**：`npm run ci` 全绿；改坏任一条不变量 → 对应测试失败

## P1 引擎正确性（最高优先 —— 交易模拟的命门）
- [ ] 引擎单测补齐：订单生命周期（挂→触发→成交→撤销）、保证金/强平价（全仓 vs 逐仓、币本位）、滑点与冲击、手续费、资金费、部分成交
- [ ] **双向持仓（多空双开）**：`Account.positions` 多仓位模型，各方向独立保证金/强平价/盈亏，可分别平仓
- [ ] 部分平仓（票据支持按比例/数量平仓）
- [ ] 报表数值对账：逐笔重算 ↔ 会话汇总（胜率/PF/期望/最大回撤/R 倍数）必须一致
- **验收**：`tests/model.test.ts`/`orders.test.ts` 覆盖上述每条；一段固定交易序列的报表与手工计算一致

## P2 架构瘦身（可维护性）
- [ ] 拆分 `App.tsx`（1642 行 → 每文件 ≤400 行）：`features/dataset`、`features/replay`、`features/trading`、`features/panels`、`features/layout`
- [ ] 状态收敛：领域状态（数据集/会话/账户/订单）与临时 UI 状态分离，去掉 `latest/sessionStartRef` 这类"读最新一帧"的隐式耦合
- [ ] 质量门阈值收紧：超 800 行即失败；清空 `SIZE_DEBT`
- **验收**：质量门告警为 0；功能回归（P4 冒烟套件）全绿

## P3 训练产品化（决定"完整训练"体验）
- [ ] 训练计划：按品种/周期/难度的课程与目标（如"连续 20 单不违反纪律"）
- [ ] 每单复盘：自动记录入场/出场截图锚点 + 一笔一评（理由标签：突破/回踩/逆势…）
- [ ] 统计看板：按方向/品种/时段/星期/持仓时长切片，弱项诊断与建议
- [ ] 训练闭环：连击(streak)、纪律分、错题本（违规单自动归档）
- [ ] 报告导出：会话报告（含权益曲线、交易明细、图片锚点）→ PDF/CSV
- **验收**：能生成一份"本次训练报告"，且指标与档案库可交叉核对

## P4 UX 与可靠性（用户直接感知）
- [ ] 指标细粒度管理：逐个添加/删除/改参数（当前以模板为主）
- [ ] 日期区间对话框完整应用链路 + 预设
- [ ] 端到端冒烟套件入库（`tests/e2e/`，用壳的 `--eval` 驱动，含真实指针事件）
- [ ] 降级矩阵：离线/慢网/无缓存的每个组合都有明确提示且可用
- [ ] 窄窗与移动布局；快捷键全覆盖与可自定义
- **验收**：e2e 套件可在 CI 一键跑；断网全流程可用

## 工作方式（工业标准）
1. 改动前：读代码 → 写/改测试 → 再动实现
2. 每次提交：`npm run ci` 必须全绿；提交信息写清「现象 / 根因 / 验证证据」
3. 每条不变量：先加回归测试，再改实现
4. 验收口径：可复现的命令 + 观测字段（`data-*` / 探针），不接受"看起来好了"
